# JavaQuest v2 题库创作规范（编程题 · 唯一标准）

> 目标:全部为**真编程题**。禁止选择题/填空题/输出预测题。禁止"打印字面量"式题目。
> 参照样例:`data/problems/ch01.js`(黄金标准,先读它再动笔)

## 一、文件与章节结构

一章一个文件:`data/problems/chNN.js`(NN=01..14),**单一作者,禁止并发追加**。

```js
window.JQ_PROBLEMS = window.JQ_PROBLEMS || [];
window.JQ_PROBLEMS.push({
  ch: 4,
  title: "数组与线性结构",          // 章标题
  courseRef: "黑马第4章-数组 / 第7章-算法训练",
  levels: [ /* 15 关, order 1..15, 每关 1 题 */ ]
});
```

每章 **15 关**,按 `order` 1→15 递进,分 5 个阶段(每阶段 3 关):

| order | stage | 认知目标 | 形态要求 |
|---|---|---|---|
| 1-3 | 基础语感 | 语义精确、边界正确 | `method`,含边界隐藏用例 |
| 4-6 | 组合运用 | 多步拆解、结构选型 | `method`,≥1 个隐藏用例 |
| 7-9 | 综合拆解 | 递归/双指针/前缀和/排序 | `method`,隐藏用例覆盖极端输入 |
| 10-12 | 算法深潜 | 复杂度与正确性 | `method` + **`stress` 随机对拍** |
| 13-15 | 创新挑战 | 系统设计与知识体系 | **`design`**(操作序列) 或 stress;第15关为本章 Boss |

## 二、题目对象 schema

```js
{
  id: "ch04-L10", order: 10, stage: "算法深潜",
  title: "最长无重复子串",
  tags: ["滑动窗口","哈希表","O(n)"],
  q: "题干:明确输入参数含义、返回值、约束(n≤1e5)、边界与复杂度要求。",
  mode: "method",                       // method | design | stress | stdin
  entry: { method: "solve", params: ["String"], ret: "int" },
  starter: "public class Main {\n    public static int solve(String s) {\n        // TODO\n        return 0;\n    }\n}\n",
  solution: "完整参考实现",
  tests: [
    { name: "样例1", args: ["abcabcbb"], expect: "3", cmp: "exact" },
    { name: "边界", args: [""], expect: "0", cmp: "exact", hidden: true }
  ],
  hints: ["用 last[c] 记录字符最后出现位置"]
}
```

### 类型支持(entry.params / ret)
`int long double boolean char String int[] long[] double[] boolean[] char[] String[] int[][] long[][] String[][] List List<String> List<Integer> Object`

- `List<E>` 支持元素类型 `int/long/double/boolean/char/String`(以及包装类);编码与 `String[]` 相同。
- `Object` 参数按内容自动推断(整数→`Integer`/`Long`,小数→`Double`,`true/false`→`Boolean`,其余→`String`)。

### 参数编码(tests[].args,每个元素是字符串)
- 标量:直接写,如 `"42"`、`"abc"`
- 数组:`"1,2,3"`;空数组 `""`
- 二维数组:行用 `;`,列用 `,`,如 `"1,2;3,4"`
- String[]:`|` 分隔,如 `"ab|cd"`(**字符串内不可含 `|` `;`**)
- List:同 String[] 编码
- ⚠️ 不要用 `*` `?` 等 glob 字符作为参数值(部分 shell 环境下会被展开),需要乘法符号时用 `"mul"` 之类词代替。

### 比较器 cmp
| 值 | 语义 |
|---|---|
| `exact`(默认) | 去行尾空白后完全一致(字符串答案带不带引号都接受) |
| `tokens` | 按空白分词比较(容忍换行/多空格) |
| `float` | 数值逐个按误差比较;可写 `{ type:"float", eps:1e-9 }` 指定误差 |
| `unordered` | 元素级排序比较(答案顺序无关;`[1,2]` 与 `[2,1]` 视为相同) |
| `set` | 元素级去重后排序比较 |
| `lines` | 按行比较 |

### stress 模式(算法深潜/创新阶段必备)
```js
mode: "stress",
entry: { method: "solve", params: ["int[]"], ret: "int" },
stress: {
  iterations: 300, seed: 20260101,
  gen: `public class Gen { public static String[] gen(java.util.Random r){ /* 返回参数 token 数组,与 params 一一对应 */ } }`,
  ref: `public class Ref { public static int solve(int[] a){ /* 暴力/参考实现,签名与 entry 完全一致 */ } }`
}
```
- `Ref` 必须是**正确但可以低效**的参考实现;`Gen` 必须覆盖各种规模与边界(含 n=0/1)。
- 判题时用 `Gen` 生成随机输入,`Ref` 与用户实现结果必须完全一致。
- 对拍不一致或你的实现抛异常 ⇒ 判 **WA**(答案错误),不是 RE。

### design 模式(创新阶段)
```js
mode: "design",
entry: { className: "LRUCache" },
ops: [["LRUCache",[2],["int"]],["put",[1,1],["int","int"]],["get",[1],["int"]]],
expect: ["null","null","1"],
cmp: "exact"
```
- 首元素是构造操作(类名),`args` 为构造参数;后续每个操作 `[方法名,[参数...],(可选)类型数组]`。
- **类型数组可省略**:省略时判题器按目标方法的真实签名自动解析参数(`Auto`)。存在**同名同参数个数的重载**时必须显式声明类型,否则报"方法签名歧义"。
- 构造器支持带参数,支持 `private` 构造器(`setAccessible` 已开启)。
- 用户代码里 `public class Main` 可留空/占位,目标类为**非 public 类**定义在同一文件(文件名 Main.java)。
- 无返回值的方法在 expect 里写 `null`;返回值按 `Ser.ser` 规范化(`int` → `1`,`double` → `1.0`,`String` → `"x"`,`int[]` → `[1,2]`,`List` → `[1,2]`,`boolean` → `true`)。
- ⚠️ **不要在任何 op 里返回对象实例**(会序列化成含身份哈希的 `Foo@1a2b3c`,期望值无法稳定);需要时返回 `String`/`int` 等值类型。
- 可写多组序列:`opSets: [{ name:"基础", ops:[...], expect:[...] }, { name:"隐藏边界", ops:[...], expect:[...], hidden:true }]`。

## 三、内容质量硬性要求

1. **禁止打印题**:不得出现"输出一行 Hello"这类仅考察 `System.out.println` 的题目;所有 `method` 题必须实现真实逻辑。
2. 每题 `tests` **≥3 条**,其中 **≥1 条 `hidden:true`**(边界/极端规模)。
3. 题干必须写明:参数含义、返回契约、约束规模、边界情况;可选给出复杂度要求。
4. 难度递进:同章 order 越大,思维难度越高(order 1 也必须有边界陷阱,不许无脑)。
5. 覆盖计算机思维:位运算、递归、复杂度、数据结构选型、状态机、不可变性、设计模式、边界与溢出。
6. 语言:题干中文,代码英文;禁止复制受版权保护的原文。

## 附：内容质量门禁（v2.2 起）

出题/改题后除功能校验外，还需满足：

1. **不得跨章同题**：与另一章的题在"题干 + 解法"上实质相同即视为同题（仅方法名或数据规模不同不算换题）。
   跨章比对用 `node tools\content-audit.mjs`（需在 java-quest 根目录运行）。
2. **同章标题唯一、解法指纹唯一**：由 `verify-problems.mjs` 自动拦截。
3. **难度看语义不看行数**：位运算进位、取模防溢出、别名语义这类题参考实现很短但很难，**不要**因为解法短就判定它简单。
4. **随机数据要有分布意识**：`Gen` 必须覆盖边界，而不只是均匀随机。
   例：两数相加要构造"相加得 0"（进位链最长）、前缀更新要放 `INT_MIN`、大规模性能点要用**固定用例独立 JVM** 考核而不是塞进随机循环（会累积超时）。
5. **返回值规模受命令行参数限制**：判题通过 argv 传参，单个用例的期望值过大（数万个元素）会把参数撑爆导致 RE。
   经验值：参数总量控制在数十 KB 以内（4000 个 int 约 22KB 是安全的）。
6. **期望值写法**：`String` 结果带引号（`"abc"`）、`String[]` 写成 `["a","bb"]`；`void` 写 `null`；`double` 整数结果显示为 `1.0`。
