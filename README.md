# JavaQuest v2 ☕ 编程闯关游戏

面向 Java 初学者的**真编程闯关游戏**：14 章 × 15 关 = **210 道编程题**，全部由本机 JDK 真实编译运行评测。
题库内容对齐黑马 Java 课程章节，但每章按「能力递进」重新设计，**没有一道选择题/填空题/打印题**。

| 项目 | 状态 |
|---|---|
| 版本 | v2.2（内容打磨完成） |
| 关卡 | 210 关 / 14 章（method 126 · stress 42 · design 42） |
| 章节 BOSS | 14 个，全部具备「公开序列 + 隐藏边界序列」两阶段判定（隐藏序列共 181 步） |
| 成就徽章 | 12 枚；称号 9 级 |
| 自动验收 | **4 道护栏全绿**（详见第四节） |

## 一、怎么玩

**环境要求**：Node.js ≥ 18（开发环境为 24）、**JDK 17 或更高**（开发环境为 21），且 `java` 与 `javac` 都在 `PATH` 上。

```bash
git clone https://github.com/laizitengwanggededaozei/JavaQuest.git
cd JavaQuest
node tools/serve.mjs 4319
# 浏览器打开 http://127.0.0.1:4319
```

> 必须通过本地服务打开（不要用 `file://` 直接打开 index.html）：判题需要服务端调用本机 `javac` / `java`。

**玩法**：每章 15 关严格递进，**通过当前关才解锁下一关**；每关写出真实代码 → 「提交评测」→ 逐用例反馈 → 通关获得 XP 与称号，通关后可查看参考实现。

## 二、关卡体系（每章 15 关 = 5 阶段 × 3 关）

| 关 | 阶段 | 考什么 | 判题方式 |
|---|---|---|---|
| 1–3 | 基础语感 | 语义精确、边界与溢出 | 函数实现 + 隐藏边界用例 |
| 4–6 | 组合运用 | 多步拆解、结构选型 | 函数实现 + 隐藏边界用例 |
| 7–9 | 综合拆解 | 双指针/前缀和/递归/排序 | 函数实现 + 极端输入隐藏用例 |
| 10–12 | 算法深潜 | 复杂度与正确性 | **随机对拍** + 作者手写边界用例 |
| 13–15 | 创新挑战 | 系统设计与知识体系设计 | **操作序列设计题**；**L15 为章节 BOSS** |

**随机对拍**是核心防"碰巧过样例"机制：判题器用题目自带的随机生成器造几百组数据，把学生实现与独立参考实现逐一比对，任何一组不一致就给出具体反例。

**BOSS 战（L15）**：进入关卡即开始 10 分钟倒计时，判题被拆成两个阶段——先通过公开序列，再通过一条**学生看不到的隐藏边界序列**（容量为 1、空输入、溢出回绕、不可变契约等极端情形）。阶段进度实时显示，全部通过才算击破并记录用时与提交次数。超时不判负，可返回地图重新开战（提交次数会保留）。

**成就徽章（12 枚）**：初次编译 / 首章通关 / 三章连破 / 十四柱 / 一击必杀 / 十连完美 / 算法深潜者（通过全部 42 个随机对拍关）/ 架构使徒（全部 42 个设计关）/ BOSS 终结者 / BOSS 全破 / 稳如老狗（同一关失败 20 次后拿下）/ 全量通关。解锁时右下角弹出提示，战绩页有徽章墙。

## 三、判题内核能力（`tools/judge-core.mjs`）

- **四种模式**：`method`（反射调用函数）、`design`（按操作序列调用对象，支持带参/私有构造器）、`stress`（随机对拍）、`stdin`（标准输入输出）。
- **判决分类**：`CE` 编译错误 / `TLE` 超时 / `MLE` 内存超限 / `RE` 运行时错误 / `WA` 答案错误 / `AC` 通过；每个用例独立 JVM，互不污染。
- **调试友好**：`System.out` 打印不影响判定（可放心边写边打印）。
- **比较器**：`exact` / `tokens` / `float`（可配 `eps`）/ `unordered` / `set` / `lines`；字符串答案带不带引号、转义与否都视为同一答案。
- **隐藏用例**：只回传判决结果，不回传期望值，避免剧透。
- **教学友好**：答错时把判决翻译成"下一步该改什么"（超时→复杂度、RE→越界/除零、WA→对照期望实际）。
- **多阶段操作序列**：`opSets` 支持一组公开序列 + 若干隐藏序列，用于 BOSS 战与设计题分级判定。

## 四、质量保障（四道护栏）

改完代码或题库后，按顺序跑这四道；**任何一道失败都视为回归**。

| # | 命令 | 覆盖 | 当前结果 |
|---|---|---|---|
| 1 | `node tools/judge-selftest.mjs` | 判题内核：判决矩阵 20 项 + 比较器 5 项 | ✅ 全部通过 |
| 2 | `node tools/verify-problems.mjs data/problems/chNN.js` | 单章题库：schema / 顺序 / 隐藏用例 / starter 可编译 / **solution 必 AC** / 题面接口一致性 / 同章防重题 | ✅ 14/14 章 |
| 3 | `node tools/ui-smoke.mjs` | 前端接线：stub DOM 跑地图渲染、开卡、提交、徽章解锁、BOSS 计时与阶段 | ✅ 全部通过 |
| 4 | `node tools/e2e-check.mjs` | 端到端（需先启动服务）：题面契约、隐藏用例不泄露、公开样例隔离、畸形 URL、数据目录拦截等 8 项 | ✅ 全部通过 |

另有一个可复用的内容体检工具：

```bash
node tools/content-audit.mjs   # 解法指纹比对 + 跨章接口签名统计 + 章内规模分布
```

**为什么需要护栏 3**：v2.0 上线后出现过"点击第一关没反应"——模板里调 `JQ2UI.open(id)`，代码里却只定义了 `openLevel`，点击等于调用不存在的函数。这类接线故障**编译器抓不到、题库校验也抓不到**，只能靠真实执行渲染路径发现。

### 接口

| 接口 | 说明 |
|---|---|
| `GET /api/problems` | 题库（只含题面与公开样例，不含参考实现与隐藏用例） |
| `POST /api/run` | 只跑公开样例（快速自测） |

## 六、存档

进度保存在浏览器 `localStorage`，键为 `javaQuest.v2.save`；代码草稿按关保存为 `jq2.draft.<关卡id>`。
存档字段：`solved / attempts / xp / badges / best / streak / boss`；旧档缺字段会自动补齐。
「🔄 重开」可重置全部进度与草稿。

## 七、给后续出题者

先读 [题库规范v2.md](tools/题库规范v2.md)，再参照黄金样例 `data/problems/ch01.js`。新增/修改题库后必须自检：

```bash
node tools/verify-problems.mjs data/problems/chNN.js
node tools/content-audit.mjs      # 跨章比对(需要全局视野, 验证器只看单章)
```

校验器会检查：schema、`order` 连续、每关用例数与隐藏用例、starter 可编译、**solution 必须 AC**、
**题面声明的接口必须与判题实际调用的接口一致**（防止"按题面写却必然失败"的关卡）、
同章标题与解法指纹不得重复、BOSS 必须具备公开+隐藏两组 `opSets`。
